# 需求与成功标准

题号：2，内容任务规划 Agent。用户为运营人员，目标是在活动预算与截止时间内得到可保存的内容活动方案。

## 输入与范围

- 输入：`request_id`、`topic`、非负 `budget`、正数 `deadline_hours`。
- 默认场景是虚构新品推广。素材、事实、制作费用与耗时均为合成数据。
- 预算仅包含最终计划的素材使用、内容制作、审核费用。废弃方案、Agent 工具调用及真实 API 费用不计入活动预算。
- 业务步骤按串行耗时相加，内部使用分钟；不包含 Agent 程序运行时间。
- 输出活动计划与 Agent Trace。保存是保存规划草稿，业务步骤没有实际执行，更不代表已发布。
- 无前端、数据库服务、部署或多 Agent。跨进程失败步骤续跑不在本次范围内。

## 必须交付

活动主题与约束；素材 ID 与事实引用；脚本；带依赖、状态、费用和耗时的业务步骤；费用与耗时合计；双重约束检查；实际保存结果或未完成原因。

## 验收标准

1. 正常请求生成方案，通过双重约束后写入实际 JSON 文件。
2. 缺预算或截止时间时输出 `needs_input` 及缺失字段，无模型调用或方案保存。
3. 超预算观察能反馈给模型，模型可选择替代素材或内容形式；新方案重新估算。
4. 工具失败被记录并反馈；此前成功的产物不丢失。由模型决定重试、改方案或终止。
5. 同 ID 同输入复用已有保存方案，零新增模型/工具调用；同 ID 不同输入返回 `conflict`，原文件不变。
6. 无可行方案返回 `incomplete`，保留已尝试方案及预算/时间缺口。
7. 预算通过而时间超限时禁止保存；修改方案后旧估算失效。
8. 实际模型调用数与动作步数都受配置上限约束；模型不能凭结束声明制造成功状态。

## LangGraph 重构范围

在原功能基础上以 StateGraph 接管执行循环，明确 State、模型决策节点、工具执行与观察更新、条件路由和终止条件。保留所有核心验收，增加图状态、路由、上限与检查点测试。采用进程内 InMemorySaver，不声称已实现恢复。

Mock 测试只能验收执行机制。已另外采集两条 DeepSeek 真实 API 路径，分别体现参数/预算反馈下的调整与工具故障后的重试，详见评估文档。
